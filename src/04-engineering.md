# 4. ออกแบบระบบอย่างรับผิดชอบ

จริยธรรมควรถูกแปลงเป็นข้อกำหนดทางวิศวกรรมที่ทดสอบได้ ไม่ใช่ถ้อยคำในเอกสารนโยบายเพียงอย่างเดียว

## ข้อกำหนดที่นำไปตรวจสอบได้

| หลักการ           | ข้อกำหนดเชิงระบบ                                      | หลักฐานที่ควรตรวจ                                    |
| ----------------- | ----------------------------------------------------- | ---------------------------------------------------- |
| ความจำเป็น        | เก็บข้อมูลเฉพาะที่ตอบวัตถุประสงค์ที่อนุมัติ           | รายการข้อมูลและเหตุผลของแต่ละฟิลด์                   |
| ได้สัดส่วน        | ใช้วิธีที่รบกวนสิทธิน้อยที่สุดและได้ผลเพียงพอ         | เปรียบเทียบทางเลือกและผลกระทบ                        |
| ความถูกต้อง       | แสดงความไม่แน่นอนและให้มนุษย์ยืนยันก่อนดำเนินการ      | ผลทดสอบ false positive/false negative และบันทึกทบทวน |
| จำกัดวัตถุประสงค์ | บังคับสิทธิการค้นและห้ามนำข้อมูลไปใช้ซ้ำโดยไม่มีอำนาจ | access control, audit log และการอนุมัติ              |
| จำกัดระยะเวลา     | ลบข้อมูลอัตโนมัติเมื่อครบกำหนด                        | รายงานการลบและการทดสอบกู้คืนข้อมูล                   |
| ความปลอดภัย       | เข้ารหัส ควบคุมบัญชี และเตรียมรับมือเหตุรั่วไหล       | threat model, ผลทดสอบ และแผนตอบสนองเหตุ              |
| ความรับผิดชอบ     | ระบุเจ้าของการตัดสินใจและช่องทางอุทธรณ์               | ผู้รับผิดชอบ SLA การแก้ไข และสถิติคำร้อง             |

## มาตรการป้องกันความผิดพลาด

- แยก **การแจ้งเตือน** ออกจาก **การตัดสินใจ**: คะแนนหรือผลจับคู่เป็นเพียงสัญญาณให้ตรวจสอบ
- ให้เจ้าหน้าที่เห็นเหตุผลและข้อจำกัดของผลลัพธ์ ไม่แสดงเพียงไฟเขียวหรือไฟแดง
- มีขั้นตอนยืนยันตัวตนหลายแหล่งก่อนดำเนินการที่กระทบสิทธิ
- ทดสอบในสภาพจริงหลายแบบและประเมินความผิดพลาดแยกตามเงื่อนไขที่เกี่ยวข้อง
- มีช่องทางให้ผู้ได้รับผลกระทบตรวจสอบ แก้ข้อมูล และร้องเรียนได้
- ซ้อมรับมือข้อมูลรั่วไหล ระบบขัดข้อง และการแจ้งเตือนผิดเป็นระยะ

## การประเมินก่อนนำไปใช้

ก่อนขยายระบบ ให้ทีมสหสาขาทำการประเมินผลกระทบด้านสิทธิและความเป็นส่วนตัว ระบุทางเลือกที่รบกวนน้อยกว่า กำหนดตัวชี้วัดหยุดหรือทบทวนโครงการ และเปิดเผยข้อมูลที่ไม่เพิ่มความเสี่ยงต่อบุคคล เช่น วัตถุประสงค์ ระยะเวลาเก็บ และผลตรวจสอบความแม่นยำ

> การออกแบบที่รับผิดชอบไม่ใช่การรับประกันว่าจะไม่มีข้อผิดพลาด แต่คือการลดโอกาสเกิด ทำให้ตรวจพบได้ จำกัดความเสียหาย และเยียวยาผู้ได้รับผลกระทบได้จริง
